## Resumable server worker

The initial 1991 command finished normally; it was a one-time staging command, with no continuing worker installed. On 25 September, following the user's request to continue on the server, a separate worker was installed at `/home/pollmedia/census-worker/`. Its private virtual environment uses `census-worker-requirements.txt`; it never loads the web application or its database credentials.

The pollmedia user's cron invokes `run_census_server_worker.sh` every five minutes. The Python worker holds an exclusive file lock, so overlapping invocations exit without competing writes. It uses low CPU/I/O priority, a 1.5 GiB process address-space limit, a six-hour invocation timeout, a 10 GiB free-disk reserve and a 1.5 GiB available-memory guard. Cron runs independently of the laptop, SSH session and Codex. An interrupted workbook restarts safely; completed original hashes are reused. Failed packages retain an error and retry no sooner than 30 minutes later. An empty queue is reported as `waiting_for_queue`, not ongoing extraction.

The first queued package is `pollmedia-census-2001-2011-20260918.zip`, SHA-256 `7d9c59d79880b8a0aa551c3398c63a986913ecda4ae7d3f21e93fe57fd9d0170`, verified on the server. It has five extraction/source references but only three distinct original workbook hashes. The three rural/total/urban references share one original; its full raw worksheets are extracted once and all reference metadata is retained. The worker preserves packaged extraction JSON as evidence and independently extracts original workbook cells into `census-review.sqlite`. These rows include headers/notes and overlapping geographic levels, so their counts are not comparable to filtered, published rows or population counts. XLSX formulas are retained as text; XLS cached values and cell types are retained, with the original XLS preserved for formula inspection. This package does not establish all-district or national historical completeness.

Compact status is in `status.json`; job errors, workbook counts and source references are in the review SQLite database. Originals are content-addressed in `originals/`, and package manifests/extractions are in `package-evidence/`. Queue JSON files in `queue/` specify a package basename and expected SHA-256; ZIP files are placed in `packages/` before queueing. The worker checks package, original and packaged-extraction checksums. It currently accepts the existing Census export package format containing XLS/XLSX originals; PDF OCR and new source discovery require separately reviewed collection/adapters before queueing.

Worker code and tests are versioned in Git. The worker directory, original files, export packages and review databases are outside Git. A later `git pull` deploys code only; verified staging data still needs an explicit compatible live import after review. No live code pull, schema migration or PostgreSQL write was performed by this worker setup.
